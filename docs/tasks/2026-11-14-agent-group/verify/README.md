# 试跑记录

`pilot.py` 是规格定稿前的验证工具，不进产品代码。它复用书斋的 `LLMRouter` 和平台搜索 `grounded_search`，用真实模型把讨论群流程（group）和单模型对照（solo）各跑一遍。从 `backend/` 目录用后端虚拟环境运行；运行环境里若有 `ANTHROPIC_BASE_URL` 要先去掉。平台 Key 只按变量名从环境读取。

模型搭配：主持人与撰稿人 `dashscope:qwen3.8-max`，调研成员 `deepseek:deepseek-flash`，反方质疑与验收人 `ark:doubao-seed-2-1-pro-260915`，单模型对照 `dashscope:qwen3.8-max`。搜索按每次 2 颗草莓折算。

## 三次试跑

| 试跑 | 题目 | 讨论群 | 单模型对照 | 备注 |
|---|---|---|---|---|
| pilot-01 | AI 分身与陪伴类产品竞品对比 | 3 轮、1 版稿、验收未过；28 次模型调用、25 次搜索；169 颗、221 秒 | 2 次模型调用、8 次搜索；37 颗、68 秒 | 第一版流程 |
| pilot-02 | 同上 | 两处校验失败后中止，没有可比成果 | 未跑 | 修正「再查一轮」次数后的流程 |
| pilot-03 | 按效果付费怎么落地 | 3 轮、2 版稿、验收 6 条全过、0 次校验失败；31 次模型调用、45 次搜索；270 颗、392 秒 | 2 次模型调用、9 次搜索；41 颗、71 秒 | 当前流程 |

三次合计模型成本约 3.5 元。千问搜索每次实耗约 4,900–5,100 token，三次试跑共 87 次搜索，0 次失败。

## 试跑暴露并已修正的问题

1. 主持人连续选「再查一轮」，拖到末轮才撰稿，验收不过也没有返工机会。改为只有 `round ≤ max_rounds − 2` 才允许再查。
2. 调研成员看不到自己前几轮的结论和针对自己的质疑，口径矛盾三轮没解决。笔记一步带上本人的历史要点与未被驳回的质疑。
3. 撰稿人与验收人拿到全量来源表（一次 169 条），多耗一倍 token。只给被要点引用过的来源。
4. 验收人看不到来源原文，却要求页码。引用检查限定为「关键事实没标来源编号也没注明是推断」；验收人给的原句若不是成果里的逐字片段就丢弃（pilot-01 三条里一条不是）。
5. 主持人把成员写成中文名而不是代号，连续两次校验失败。两种写法都接受，报错里列出合法取值。
6. 主持人给撰稿人的要求超过字数上限，连续两次校验失败。字数只在提示词里要求，校验只查结构，超长在落库前截断。
7. 完成标准写成「每款都必须有价格」而公开资料查不到，验收必然不过。立项提示词要求标准现实，查不到的写成「有则列出，查不到要注明」。
8. 主人在诉求里给出的信息被当成「没有来源」。撰稿与验收提示词写明这类信息不需要来源。

## 盲读

两次都把讨论群成果与单模型成果随机标成甲、乙交给作者，对应关系存在仓库外，作者选完才揭晓。

- pilot-01：作者点选的是单模型那份；揭晓后作者表示「我刚才选错了，我还是希望讨论群写的」。
- pilot-03：作者点选的仍是单模型那份；揭晓后作者表示「我又点错了，其实甲更好」（甲是讨论群那份），并决定「不再比了，按现在的流程做」。

规格作者读后的看法（不代表作者）：pilot-03 里讨论群那份结论偏保守、案例覆盖比单模型窄，建议过改成「一位主笔先通查并写初稿，其他成员只补事实、查证、挑错」再测；作者没有采纳，决定按当前流程做。成本上讨论群是单模型的 4.6–6.6 倍，耗时是 3–5.5 倍。
