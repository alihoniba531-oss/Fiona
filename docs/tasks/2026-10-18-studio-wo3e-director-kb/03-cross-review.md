# 交叉审核：导演出稿后交给千问 3.8 Max 审（作者 2026-10-18 确认）

作者要求（2026-10-18）：DeepSeek 出完剧本和分镜后，路由到 Qwen 3.8 Max，结合小说审核剧本逻辑和分镜。

## 1. 行为
- 导演模型完成以下两类任务后，自动排一个审核任务：
  - 第 4 期的本集剧本；
  - 拆镜，包括本期的 `shot_plan` 和试拆。
- 审核用的模型是项目设置 `review_provider`，默认 `qwen`（qwen3.8-max）。可选 `claude`、`qwen`、`deepseek`、`off`。
- 审核模型和导演模型相同时允许运行，但界面要提示「同一模型自审，效果有限」。
- 审核结论只作提示，不自动退回、不淘汰版本（计划第 8 条）。
- 作者可以点「按审核意见重拆 / 重写」，审核意见会作为反馈附进导演的下一次调用。
- 计费口径与其他导演调用一致：先预留额度，受日上限和单次上限约束。

## 2. 审核任务 `cross_review`
- 在 `brain_tasks.TASKS` 里登记，提示词放在 `prompts/cross_review.md`。
- 素材一律按不可信数据处理，沿用 brain 现有的措辞。

**输入**：

| 字段 | 内容 |
|---|---|
| `source_text` | 原文。第 4 期是本集对应的小说快照正文；试拆时是 `scene_text` |
| `bible` | 人物、地点、道具总表摘要（可选） |
| `continuity` | 上一集或上一场的末状态（可选） |
| `adaptation_scale` | 改编尺度：忠实 / 适度 / 自由 |
| `script` | 本集剧本（可选） |
| `shots` | 分镜（可选） |

**审核四个方面**：
1. **logic 剧本逻辑**：因果是否成立，人物动机，时间线，谁在什么时候知道什么，伏笔与回收，与总表有没有矛盾。
2. **fidelity 忠实度**：按改编尺度对照原文，看关键情节有没有漏掉或改错，有没有编出与原文冲突的事实，人物说话的口吻对不对。
   - 「自由」尺度只查冲突，不查遗漏。
3. **storyboard 分镜**：剧本的每个节拍是否都有镜头，镜头顺序，台词有没有落到具体镜头，时长合计是否在目标窗口内。
4. **continuity 连续性**：道具归属、站位左右、服装伤妆、视线方向，在镜头之间是否一致。

**输出 schema**：

```
{"verdict": "ok" | "issues",
 "summary": str,
 "issues": [{"severity": "must" | "should",
             "kind": "logic" | "fidelity" | "storyboard" | "continuity",
             "where": str,
             "source_ref": str | null,
             "problem": str,
             "suggestion": str}]}
```

- `where` 填镜号、场号或剧本段落。
- `source_ref` 填原文位置。
- `issues` 最多 30 条，`must` 在前。

## 4. 第 4 期（写进计划，本期不做）
- 本集剧本完成后，用小说快照正文审一次。
- 每场拆镜完成后，用剧本加原文审一次。
- 审核结论并入 G2 报告，与知识库检查的 warning 分开列。
