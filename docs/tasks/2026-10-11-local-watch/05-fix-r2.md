## R2-1 「不需要提醒」被当作判断失败（必须，修订 02-spec 2.3）

**现状**：模型正常返回 `{"alert": false, "summary": ""}` 时，因为 summary 为空被判为失败：每次都会打一条 WARNING，并写一条失败的 trace。

**改法**：只有 `alert` 为 `true` 时才校验 summary 必须是 1–80 字；`alert` 为 `false` 时 summary 可以为空或任意内容，直接视为成功判断，判定结果是「不提醒」。

**测试**：
- `alert: false` 加空 summary：不提醒、不打 WARNING、trace 标记为成功；
- `alert: true` 加空 summary：判为失败。

## R2-2 数值规则不识别 Unicode 负号（必须）

**现状**：`−`（U+2212）和全角 `－`（U+FF0D）不被当作负号，「涨幅 −5.2%」被解析成 +5.2。

**改法**：提取数字前，先把 `−`、`－`、`﹣`、`‒`、`–` 统一换成 `-`，把全角数字、全角小数点、全角百分号换成半角。

**测试**：以上几种写法都被正确解析为负数，`>=`、`<=` 规则判定正确。

## R2-3 前端实时插入的提醒正文与库里不一致（必须）

**现状**：前端拼接的标签用的是规则名，后端落库用的是「窗口应用名，没有才用规则名」。用户刷新后，看到的文字会变。

**改法**：`GET /local-watch/alerts` 新增返回字段 `content`，即落库的完整消息正文。前端直接使用 `content` 插入消息，不再自行拼接。前端测试的期望值相应改为使用 `content`。

## R2-4 伪造令牌可以抢占数据库写锁（必须）

**现状**：未登录请求只要带一个随意编造的 Bearer 令牌，设备鉴权就会去抢一次 SQLite 写锁，而且没有按 IP 限流。

**改法**：
- 设备鉴权先用普通 SELECT 按哈希查询；只有查到有效设备时才更新 `last_seen_at`。更新至少间隔 60 秒，避免每次请求都写库。
- 鉴权失败（401）的请求按客户端 IP 限流：每分钟 30 次，超出返回 429。
- 限流计数要在参数校验和查规则之前，确保无效请求也被计数。观察上报的「每设备每分钟 60 次」限流同样放到最前面。

**测试**：
- 伪造令牌不触发写操作（用 mock 断言没有执行 UPDATE）；
- 超过 IP 限流时返回 429；
- 有效设备 60 秒内多次请求只写一次 `last_seen_at`。

## R2-5 小修（必须）

1. **索引**：`watch_devices(token_hash)` 已经是 UNIQUE，无需改动；新增 `watch_rules(username)`、`watch_alerts(username, id)`、`watch_alerts(rule_id, id)` 三个索引，写法用 `CREATE INDEX IF NOT EXISTS`。
2. **心跳限流**：每个设备每分钟最多 10 次心跳。
3. **预填应用名过长**：前端用窗口预填规则时，`app_match` 截到 60 字，标题截到 60 字，避免保存时返回 422。
4. **千分位解析**：只有符合千分位格式的写法（逗号后恰好 3 位数字）才去掉逗号。`1,2345` 不按千分位解析，只取逗号前的 `1`；不得吞掉数字。
5. **隐私断言补正控**：在一条测试里先故意把新增文字写进日志，确认断言会失败，再验证真实代码不会写入日志。
