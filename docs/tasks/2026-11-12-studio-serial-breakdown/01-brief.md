# 简报：短片工作室「边写边拆」——连载中的小说建项目，新章写好后续拆

日期：2026-11-12。基线：Fiona `main` = `135253f`。

## 1. 作者的原话与场景

作者在聊天里问分身：「我是否可以根据已经写完的章节来进行进一步的剧本拆分」。分身回答：短片工作室只能用已完结的书，这本书还在写，所以建不了项目。作者随后问：「剧本拆分目前来说只能完全写完的。是不是可以边写边拆」。

我给出两种做法：
- 只放开「必须完结」：每写完一批新章，就整本重新拆解一次，已经拆过的章要重复付费；
- 续拆：同一份拆解往后追加，只为新增的章节付费。

作者选了续拆，并在 2026-11-12 定下三条：

1. **待复核章节照收，并标出来。** 连载中改了前面的章，书斋会把后面已写好的章永久标成「待复核」。这些章照样进快照、进拆解，界面上标「待复核」，由作者决定要不要管。
2. **已经拆过的章后来被改了，照常续拆，只提醒。** 续拆只拆新增的章，旧章的改动不进拆解。面板列出哪几章改过；确实需要时，作者仍可以整本重新拆解。只重拆受影响的那一段，以后再做。
3. **续拆后整份分集方案重新批准一次。** 新章的分集追加到方案末尾。已有的分集，包括作者改过的，原样保留。方案退回待批准，新增的集标出来；批准前，定妆页的付费操作暂时锁住。

## 2. 调查结论

调查做了三路只读梳理，规格作者另外亲自核对了关键代码。

- **资格**：建项目、同步和做成片共用 `studio/sources.py:61-75` 的 `_eligibility`，它要求作品「已完结、有故事圣经、全部章节 done、无待复核、不在改稿」。书斋工作台的「做成片」按钮写死只对 `completed` 显示（`NovelWorkbench.tsx:82-92`、`:294`、`:322`），分身工具描述写的是「已完结小说」（`claude_agent.py:125`、`intent_router.py:148`）。
- **快照**：
  - 读取范围取「所有章号」和 `chapters_done` 中的较大值（`sources.py:126-134`）。`chapters_range` 不过滤状态，所以逐章确认模式下，正在规划的下一章（正文为空）也会被读进来，组装时会因为「第 N 章正文缺失」而失败（`:160-166`）。
  - 防并发的签名里包含 `updated_at` 和书的 `status`（`:137-139`）。写作中的书，计费会不停改 `updated_at`，快照很可能两次重试都失败。
  - 每写完一章，`bible_version` 都会加 1（`novel/store_db.py:296`）。
- **同步与重拆**：
  - 同步只会新建一版快照，并把当前拆解整体标为 `outdated`（`sources.py:491-492`）。之后唯一的路是整本重新拆解：新建拆解、旧拆解记 `superseded_by`（`breakdown.py:222-285`）。
  - 总表 ID 由拆解 ID 派生（`breakdown.py:363`）。重拆之后，已选定的定妆图和声线全部挂在旧条目上，变成「孤儿」（`casting.py:128-132`）。
- **可以利用的接缝**：
  - 批次按「每 10 章一段」切，每段一个分集批（`breakdown_material.py:85-158`），而且模型生成的集不跨段。
  - 单元按批次顺序全量物化、重新编号（`breakdown.py:288-329`）。往后追加批次时，前面单元的编号不变。
  - 依赖存的是批次 ID，在同一份拆解里追加批次结构上可行。
  - 单批重跑已经示范了「同一份拆解换新任务、状态拨回 running」。
- **必须改的地方**：
  - `refresh` 发布方案时，把全部分集批的模型原始输出拼起来交给 `publish_plan`，后者删光再插（`breakdown.py:578-588`；`breakdown_plan.py:219-241`）。续拆后照旧这样发布，会冲掉作者对分集的编辑。
  - 批次读原文用的是整份拆解的 `snapshot_no`（`breakdown.py:450`），续拆的批次必须读自己那一版快照。

## 3. 方向

1. 连载中的书也能建项目、同步：快照只收第 1 章到第 `chapters_done` 章（done 或待复核），签名不再看 `updated_at`。
2. 新增「续拆」：同步后，如果作品写到了拆解覆盖范围之外，就在同一份拆解里追加新批次。
   - 报价只含新增章节，作者确认后才执行。
   - 续拆完成后，已发布的分集原样保留，新的集追加在末尾，方案退回待批准。
3. 入口放开：书斋工作台的「做成片」、新建项目对话框、分身工具，都对至少写好一章的书开放。

## 4. 风险

- **G0 重新批准**：续拆后整份方案退回待批准。作者重新批准之前，定妆的付费操作被锁住。这是作者选定的行为。
- **续拆进行中不能取消**：本期不提供取消，避免一份拆解停在半截状态。单批失败可以单批重跑。
- **旧章改动**：已拆部分的单元仍按旧版原文。面板会提示改过的章，但不会自动修正。
- **超长作品**：超过 300 章或 50 万字的作品，仍按现有上限拒绝。
