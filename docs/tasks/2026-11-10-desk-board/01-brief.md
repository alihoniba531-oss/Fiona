# 案头（主会话创作看板）· 简报

日期：2026-11-10　基线：main `9adf34c`（工作树干净，与远程一致）

## 1. 原始需求（作者原话）

- 「我是不是可以在主会话里面增加功能：选择相应的小说，并且进行改编剧本功能+分镜拆解功能」
- 「是不是可以优化下主聊天界面，主会话在调用写小说，编剧，导演技能的时候能有一个直观的看板，并且可以方便编辑」
- 试用时让分身改一本已建好的书的第 3 章，分身没有出书斋草稿卡：「好像弹不出来」。

真实需求归纳：讨论和创作在聊天里发生，作品的状态与条目却藏在盖住聊天的书斋 / 工作室抽屉里。作者要的是**不离开对话就能看到作品写到哪、等自己确认什么，并顺手处理**。

## 2. 已核实的事实

以下都从 HEAD 读代码或实测得到。

### 2.1 聊天里现有的小说工具（只在 Claude 智能体模式）

`list_novels`、`read_novel`、`start_film`、`draft_novel` 四个。其中没有任何一个能改一本已经建好的书。`draft_novel` 只写「新书草稿」，所以作者要求改第 3 章时，分身按工具说明没有出卡，这是正确行为，不是故障。

### 2.2 书斋（小说工坊）已有的读写口

- 读：书目、单本详情（章节列表、当前关卡、待处理留言数）、单章（正文、细纲、审校）、圣经、留言。
- 写，且都由作者亲手点：批准细纲（可带改过的细纲）、附一句话重做细纲（再次扣草莓）、留言（免费，待处理最多 5 条）、继续 / 暂停 / 恢复 / 确认完结 / 再写几章、改人物三项设定、替换某章正文。
- 替换正文的后果较重：改的是最新一章会触发重新归档；改的是旧章会把后面的章标成「待复核」，不自动重写。正文是覆盖写入，没有版本，无法撤销。

### 2.3 短片工作室已有的读写口

- 拆解与分集（WO3c）已实现：分集方案带版本号，改标题 / 变化 / 钩子、与下一集合并、拆分、挪边界、删除、插入都免费，靠 `expected_revision` 防并发；批准方案免费。拆解本身付费，走「报价 → 确认 → 开跑」。
- **逐集分镜没有正式实现。** 工作台五个阶段里「③分镜」「⑤成片」显示「这一阶段将在后续版本开放」；数据库没有镜头表。现有的 `shot_plan` 只在「试读与三家对比」和知识库「试拆对比」里对单场戏试跑，不落成每集的镜头清单。
- 更正：11-03 口头说过「逐场分镜已经实现」，不准确。分集是真的，分镜只是试跑。

### 2.4 让分身直接改既有内容，没有可撤销的底子

- 章节正文无版本；分集有版本历史但没有「回退」操作。
- 细纲重做、改最新章后的重新归档都会花草莓。
- 所以画布里「分身改完留一枚改印、可撤销」做不到；能做的是「分身出提案，作者在案头点应用」，和 `draft_novel`「模型只写免费草稿、主人确认」是同一条原则。这要一张提案表和消息上的新列，是数据模型变更。

### 2.5 主聊天页与门禁

- `frontend/app/page.tsx` 3018 行，带 UTF-8 BOM；书斋、工作室是 iframe 抽屉，占右侧三分之二并盖住聊天。
- 多份基线测试锁着 page.tsx 里的字面量（书斋与工作室 iframe 的 `src` 写法、`openNovelAt` 的定义等）。
- 设计门禁：字号只许 `text-fs-*` 令牌；`--ink3` 不许当文字色；`var(--stamp)` 只许在印章组件里用；所有 `<dialog>` 必须带 `scrim-dialog`；界面文字不加粗（跨任务约定）。

## 3. 范围建议（待作者确认）

| 期 | 内容 | 动哪里 | 依赖 |
|---|---|---|---|
| **第一期（本单）** | 案头面板与对话并排；立意、章回、分集三页用真实数据；作者亲手做的操作全部可在案头完成（批准或改细纲、重做、留言、继续 / 暂停 / 确认完结、读正文、改某一集、与下一集合并、批准分集方案）；聊天里出书斋草稿卡或工作室卡时案头自动打开并定位；每行「问分身」把一句引子放进输入框 | **只动前端**，不改后端、不加接口、不加依赖 | 无 |
| 第二期 | 分身的「改稿提案」：改某章正文、改人物、改某一集，出提案卡，作者在案头点应用；聊天回执；输入框引用条；分身读书时案头自动定位；案头里直接报价确认拆解 | 后端加提案表与工具，属数据模型变更 | 第一期 |
| 第三期 | 分镜页、成片页 | 前后端 | 工作室先做完正式拆镜（WO4）与成片 |

第一期对画布的三处取舍：

1. **分镜页先不做**，书耳上「分镜」「成片」置灰标「后续开放」，因为没有数据。
2. **状态用朱色文字标签，不画方印。** 门禁不许在印章组件之外用 `--stamp`，书斋页面也约定「状态只用文字标签」。朱色只留给「定稿 / 已批准」这一种。
3. **编辑先复用书斋、工作室现成的对话框**（细纲编辑器、单集修改框），行内直接改字放到第二期。好处是文案、校验、扣费提示和原处完全一致。

更省的替代做法（不建议，但可选）：不做案头，只给书斋和工作室两个抽屉加一个「并排窄栏」模式，让它们以 488 像素宽停在聊天右边。改动很小，但窄栏里是工作台的手机版标签页，不是一眼看全的看板。

## 4. 风险

- page.tsx 巨大且被测试锁字面量，接线只允许在规格列出的几处动手。
- 案头里的「批准细纲」「重做」「继续」会触发既有的付费写作，必须沿用书斋同一组件与同一提示文案，不另写一套。
- 案头与书斋抽屉同时开着时两边各自轮询；案头只在书处于运行态时才 3 秒一轮。
- 768 到 1439 像素宽时案头是盖在聊天右侧的抽屉，不是并排；并排需要 1440 及以上。
