## 4. 实现取舍与需要说明的地方

1. **原生 dialog 的写法**：既有 `backend/tests/test_ui_closeout_dialog_scrim.py` 固定当前仓库恰好 13 个字面量 `<dialog` 标签；新增字面量会让既有测试失败，而规格禁止改既有测试。因此 `DeskDialogs.tsx` 用 `React.createElement("dialog", { className: sourceDialogClass, ... })` 生成同样的原生 dialog，不新增字面量；运行时仍是 `showModal()` + `scrim-dialog`，焦点恢复与可见关闭按钮都在。**此说法已被 R1 取代**：R1 起改为 JSX `<dialog>`，并授权把既有测试计数改为 14。
2. **读请求作用域**：规格 T2 写「读请求与写请求各用一个 `useAccountRequest`」。实现中写请求仍是一个；读请求拆成书目/详情、聊天定位、章节对话框、分集四个作用域。原因是一个读作用域下 3 秒书目轮询会取消 5 秒分集轮询、定位请求和对话框请求。所有读请求仍经 `useAccountRequest` 并在回来后判 `isCurrent()`；`CLAUDE.md` 与 `docs/ARCHITECTURE.md` 已按实际写成「读请求按用途各一个作用域、写请求单独一个」，避免文档与代码不符。**此说法已被 R2 取代**：现在书目、详情、候选、分集方案、章节对话框、聊天定位、导出各有独立读作用域，写请求单独一个。
3. **进入动画**：drawer/sheet 打开时按 `drawerStyle` 的 360ms 水平位移进入；关闭时容器按 T2 #1 直接返回 `null`，不做退出动画。`prefers-reduced-motion: reduce` 由 `globals.css` 既有全局规则把 transition 压到 0.01ms，不新增 CSS。
4. **流式定位块首行**：既有 `test_claude_agent_frontend.py` 用 `source.index("          if (data.card")` 截取卡片处理块。定位块若以 `if (data.card)` 开头会被误截取，因此写成 `const streamedCard = data.card; if (streamedCard) { ... }`，行为与规格示例完全等价。
5. **浏览器存储**：`page.tsx` 与 `DeskDock` 访问 `window.localStorage` 的位置都包了 try/catch；`lib/desk.ts` 的读写函数本身吞掉 `getItem`/`setItem` 异常。**前半句已被 R2 取代**：`DeskDock` 现在统一经 `deskStorage()` 的 try/catch 读取 `window.localStorage`，失败时当没有存储；`page.tsx` 的访问仍在 try/catch 中。
6. **加载文案**：T6 未固定加载文案，分集页使用「正在取回分集方案…」；其余固定文案严格按 4.4。
7. **未新增依赖、未新增接口、未改后端非测试文件**。
