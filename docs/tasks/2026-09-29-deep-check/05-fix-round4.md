## 必须修复

### N1 画面为空的生图请求不再追问，直接付费乱画（M1 引入的回归）

**现状**：`chat_service.py` 的候选确认分支写成了 `intent_result = {**intent_result, "params": params, "missing": []}`，丢掉了「画面为空」的信号。

**后果**：「帮我生成图片」「帮我生成一张图片」「画一张图」「给我画一幅画」这类句子：
- 基线：追问「想生成什么画面？…」，不扣费；
- 现在：直接拿这句话本身当画面去生图，扣 10 颗草莓。

**要求**：
- 候选确认为 `generate_image` 时，只要 `explicit_image_intent` 算出的 `missing` 含 `prompt`（正则判断画面主体为空，不受模型给的短 prompt 影响），或者模型返回的 `missing` 含 `prompt`，就按基线行为追问并设置待补参数，不生图、不扣费。
- 把 `tests/test_chat_image_generation.py` 中被改掉的输入恢复为基线原文（第 42、107、118 行附近的「帮我生成图片」），断言与基线一致，并且必须通过。
- 新增参数化测试：上面 4 句空画面请求在「候选 + 模型确认」路径下都只追问、不生图、不扣费；随后回复画面描述，按待补流程正常生图。

### N2 词级替换跨词误改，简体用户也被误判为危机（M5 引入的回归）

**现状**：`_WORD_REPLACEMENTS = {"计畫": "计划", "计画": "计划"}` 对全文做子串替换，会把「设计画面」「统计画面」「設計畫面」改写成「设计划面」，从而命中 high 规则。例如：
- 「游戏设计画面里加一段跳海的动画」：基线 None → 现在 high；
- 「统计画面显示上吊人数」：基线 possible → 现在 high。

简体输入同样受影响。

**要求**：
- **删除词级替换表。** 「計畫下週跳樓」降为 possible 可以接受（按 T5 仍会收到资源），请相应修改该条测试的期望，并在报告中说明原因。
- 新增回归测试，下列句子的判级必须与基线 `656b7cf` 一致：游戏设计画面里加一段跳海的动画；我在做设计画面，主角最后跳河；这部片的设计画面有自杀镜头；统计画面显示上吊人数；遊戲設計畫面裡加一段跳海的動畫；電影設計畫面有自殺鏡頭。其中繁体句以对应简体句在基线上的判级为准。

### N3 覆盖性测试仍测不出新增规则字的遗漏（M5）

**现状**：测试收集了 safety.py 的全部汉字，但只做了「包含 让伞绳远」「交集 ≥75」这类弱断言。复核实测：新加一条内联规则 `想离开这个世界` 后，测试仍然通过，而「我想離開這個世界」判为 None。

**要求**：
- 测试里写死两份清单：「规则字 → 常见繁体/异体」和「无繁体写法的规则字」白名单。断言两者的并集**正好等于**从 safety.py 收集到的规则汉字集合。多一个字、少一个字都要失败，失败信息要点名是哪个字。
- 做正控：在临时副本里给 safety.py 加一条含新字的规则，测试必须失败。把正控过程写进报告。
- 顺带补齐复核列出的日文新字体和旧字形，映射回规则里的简体字：薬、譲、縄、気、軽、対、実、絶、眞。

## 顺带处理（可优化，改动小，一并做掉）

- **P1（TTS）**：缓存总量超限时，只丢弃被淘汰票据的 `cached_audio`，不要把票据本身删掉，避免 WebKit 在试探请求和正式请求之间拿到 404。
- **P2（交流）**：`stop_and_discard_reserved_calls` 结算时如果抛出非取消异常（例如 database is locked），做有限次重试并记日志；`/stop` 不得因此返回 500。重试仍然失败时，要保证 `recover_interrupted_exchanges` 能在下次启动时结清。补一个注入异常的测试。
- **P3（文档）**：
  - `README.md` 中 `FIONA_ALLOWED_DEV_ORIGINS` 的说明改为「只填主机名或 IP，可用 *.example.local 这类通配，不带协议和端口」；
  - `README.md` 中危机资源那一段补上：路由之前的 422 校验和 429 限流不在保证范围内；
  - `docs/ARCHITECTURE.md` 写清：被模型否决的候选句会复用本轮识别结果，不增加调用；只有「确认生图」时，生图开始前要多等一次意图模型。
