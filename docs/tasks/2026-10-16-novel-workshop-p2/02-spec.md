## 0. 背景与作者拍板（必读）

小说工坊的用法：用户只提供一个故事思路，由多个智能体按章推演并写作；用户在立项、每批审阅、每章确认（可选）和完结这几个关卡拍板。后端已经完成建书、后台运行器、关卡、草莓计费和导出。P2 负责把这些做成界面。

作者对 P2 结构的拍板（2026-10-16）：

1. **入口**：侧栏新增第 6 个书签「书斋」。桌面端用竖排书签，手机端放进底栏。
2. **承载方式**：做成独立页面 `/novels`。主页面抽屉用 iframe 嵌入 `/novels?embed=1`，做法与「世界」「设置」抽屉相同。宽屏下提供「在新页面打开」。
3. **单本书工作台**：三栏布局。左栏目录；中栏正文；右栏有「推演 / 圣经 / 留言」三个标签。关卡横幅放在页面顶部。手机上三栏改为三个标签页。
4. **推演记录**：按完整时间线展示，顺序为：主编初案 → 各顾问意见（标严重度）→ 替代走向 → 主编逐条回应（替代走向标明「采纳 / 部分采纳 / 不采纳」）→ 定稿相对初案改了什么。

作者对计费的拍板：失败重试照常计费，P2 不改计费逻辑。

## 4. 后端补两个只读接口（`routers/novel.py` 与 `novel/service.py`，P1 其余部分不动）

1. `GET /novels/{id}/bible`
   - 返回**未裁剪**的最新圣经，包括罗盘、锁定区，以及动态区的全部内容：章节摘要、卷摘要、全部伏笔、时间线、已用桥段、人物状态。
   - 校验所有权：不属于当前用户的书返回 404。
   - 开关和白名单的检查与其他接口一致。
2. `GET /novels/{id}/notes`
   - 返回该书全部留言，按时间排序。每条包含：`id`、`text`、`status`（pending 或 delivered）、`delivered_chapter`、`created_at`，以及主编回应（`adopted`、`response`，未下发时为 null）。
   - 校验所有权：不属于当前用户的书返回 404。

**测试**：两个接口都要覆盖以下情况：正常返回、越权访问返回 404、开关关闭返回 404、未裁剪内容完整（以 60 章规模的数据验证）。

  - 状态标签，状态对应的中文见 §5.4；
  - 进度「第 n / 上限 章」；
  - 草莓「已花 / 预算」；
  - 最近更新时间。

  点击卡片进入工作台。处于等待用户操作的状态（各类 `awaiting_*`、`paused`）的书，卡片上要有醒目的「待你处理」提示。
- **空态**：标题为「开始你的第一本书」，说明为「只给一个思路，几位智能体替你推演整本书。」，配一个「新建一本」按钮。
- **其他状态**：加载态和错误态使用现有组件。开关关闭（404）时提示「小说工坊尚未开放」；不在白名单（403）时提示「你的账号暂未开通小说工坊」。

### 5.2 建书向导 `/novels/new`（三步，顶部显示步骤条；可以返回上一步，已填内容保留）

**第 1 步 思路与篇幅**

- 思路输入框，上限 2000 字，显示计数。placeholder 用一条真实示例。
- 目标篇幅：最少章数、最多章数（1–200，且最少不得大于最多），每章字数（1000–4000，默认 2000）。
- 改编参数默认折叠：主要人物上限（默认 6）、每章场景上限（默认 3）。

**第 2 步 智能体与模型**（数据来自 `GET /novels/catalog`）

- 推演方式二选一：
  - 「主编出方案、顾问挑错」（critique，默认）；
  - 「主编独自构思」（solo）：选这一项时，顾问区整体置灰，并显示一句说明。
- **必选角色**（主编、写手、档案员）：显示「必选」，各配一个模型下拉框。下拉框的选项受 `allowed_models[role]` 限制。
- **审校**：默认开启，可以关闭，可以换模型。
- **顾问**（六位）：每位可单独勾选，最多选 5 位。每位附一句职责说明（取自 catalog 的 description）和一个模型下拉框。
- **模型下拉框**：
  - 每个选项显示模型的中文名，以及「每千 token 输入/输出约 x/y 草莓」；
  - 有自带模型（`catalog.byok` 可用）时，增加选项「我的模型（厂商·型号）· 不扣草莓」，取值为 `byok:self`。
- 主编旁边展示 `catalog.notice`。

**第 3 步 节奏与预算**

- 自动化方式：
  - 「每写 N 章停下来给我看」（per_batch，默认，N 取 1–10，默认 5）；
  - 「每章先给我看细纲」（per_chapter）；
  - 「全自动写到完结」（full_auto）。
- 预算：输入框填写草莓数。旁边显示：
  - 估算结果：调用 `POST /novels/estimate`，在输入变化后防抖 600ms 再请求，显示每章和整本的草莓区间，并注明「估算口径：近 20 次调用均值或基线，±20%」；
  - 当前余额：调用已有接口 `GET /strawberry`（见 `backend/routers/me.py`），以它的返回值为准。
- 提交前汇总确认：思路摘要、所选智能体和模型、篇幅、节奏、预算。点击「开始立项」后调用 `POST /novels`，成功后跳转到 `/novels/{id}`。
- 校验：每一步在前端校验后才能进入下一步，错误信息就近显示在对应字段旁。后端返回的 422 或 409 原因要显示在对应位置，或在顶部用 `ErrorNotice` 展示。

### 5.3 单本书工作台 `/novels/[id]`

**页头**

- 书名和一句话梗概（来自罗盘），以及状态标签。
- 读数：「第 n / 上限 章 · 共 x 字」「草莓 已花 / 预算」，后者附一根细进度条，用现有的刻线样式，不新增颜色。
- 右侧操作：
  - 「暂停」或「继续」，按状态显示，分别调用 `pause` 和 `resume`；
  - 「调整」：弹出 `<dialog>`，可以改预算、自动化方式、每批章数。处于 paused 或 awaiting_* 状态时，还可以改智能体的模型，调用 `PATCH`；
  - 「导出」；
  - 「删除这本书」：收进「更多」菜单，需要二次确认。
- 嵌入模式下另外显示「在新页面打开」。

**关卡横幅**（页头下方；只在等待用户处理时显示；文案和操作见 §5.4）

**三栏**

- **左栏 目录**
  - 列出章号和章名。
  - 标记图标及其悬浮说明：
    - `review_unresolved`：审校两轮未通过
    - `length_out_of_range`：长度超出
    - `deviation`：偏离细纲
    - `locked_conflict`：与锁定设定冲突
    - `edited_by_user`：你改过
    - `stale`：待复核
  - 当前正在推演的章节显示一行「正在写第 n 章…」。
- **中栏 正文**
  - 显示所选章节的正文；默认选中最新一章。
  - 「改稿」按钮切换到编辑模式：用 textarea，上限 30000 字，保存时调用 `PUT`，保存后显示后端返回的 `message`。
  - 页面底部显示审校摘要：「保留 x 条意见 · 丢弃 y 条」。可以展开查看保留下来的阻断问题，内容包括 problem 和 evidence。
  - 立项关卡（`awaiting_setup`）期间，中栏改为显示「立项卡编辑器」，见 §5.4。
- **右栏 标签：推演 / 圣经 / 留言**
  - **推演**：所选章节的完整时间线，数据来自章节接口的 `meeting`。
    1. **主编初案**：章名、本章目标、节拍列表、开头钩子和结尾钩子。
    2. **顾问意见**：按顾问分组，每条显示严重度标签（重 / 轻）、针对的部分、问题、改法；另外显示该顾问认为「值得保留」的一点。
    3. **替代走向**（反转设计师）：显示原文，以及主编的决定标签（采纳 / 部分采纳 / 不采纳）和理由，来自 `alternative_responses`；如果回应写在旧格式里，也要兼容显示。
    4. **主编逐条回应**：按 O1、O2… 的顺序对应显示每条意见。
    5. **定稿相对初案的改动**：按字段比较。章名、目标、钩子有变化的，显示「原 → 新」；节拍显示新增、删除的条数。
    6. 用户留言回应（如果有）。

    solo 模式下只显示主编裁决和理由。
  - **圣经**：数据来自 §4 的完整圣经接口，分以下几块，各块默认折叠，「罗盘」默认展开：
    - 罗盘：梗概、主题、核心冲突、主角想要什么和真正需要什么、候选结局、主线；
    - 人物卡：外形、性格、动机、当前状态；
    - 伏笔账本：open 和已回收分组显示，标出埋下的章节和回收的章节；
    - 卷摘要和章节摘要；
    - 时间线。
  - **留言**：输入框（上限 500 字）加「留言」按钮。下面是留言列表，数据来自 §4 的接口：
    - 待处理的显示「待下发」；
    - 已下发的显示下发到第几章，以及主编的回应和是否采纳。

    待处理留言达到 5 条时禁止再提交，并给出说明。

**手机**：三栏改为三个标签页「目录 / 正文 / 推演·圣经·留言」；关卡横幅固定显示在页头下方。

### 5.4 状态与关卡文案（标签文字 → 横幅内容与操作）

| status / pause_reason | 标签 | 横幅文案与操作 |
|---|---|---|
| setup_running | 立项中 | 不显示横幅；页头下方显示一行进度「主编正在生成罗盘和设定…」 |
| awaiting_setup | 等你确认立项 | 「设定已生成，看看合不合意。」中栏显示立项卡编辑器，可修改：罗盘的书名、梗概、主题、候选结局、主线；锁定区的人物（外形、性格、动机）、世界规则、文风指南。修改后点「确认立项」，调用 `setup/approve`，请求体中只放有改动的字段。422 时提示「立项修改不符合设定格式」，并尽量标出对应字段 |
| running | 写作中 | 不显示横幅 |
| awaiting_review | 等你审阅 | 「已写完第 a–b 章，看完再继续。」操作：「插一句话」（跳到留言标签）、「继续写下 N 章」（调用 `continue`） |
| awaiting_plan | 等你确认细纲 | 「第 n 章细纲已定稿。」显示细纲编辑器，字段包括章名、目标、场景、节拍、钩子。操作：「批准」（原样）、「改完批准」（调用 `plan/approve` 并附 `beat_sheet`）、「附一句话重新定稿」（调用 `plan/redo`，会扣草莓，界面上要写明） |
| awaiting_end | 等你确认完结 | 「智能体判断故事可以收尾了。」操作：「确认完结」（调用 `end/confirm`），或者「还没完，再写 N 章」（N 取 1–10，可附一句话，调用 `end/reject`） |
| completed | 已完结 | 「全书完结，共 n 章 x 字。」操作：「导出」 |
| paused / user | 已暂停 | 「已暂停。」操作：「继续」 |
| paused / budget_80 | 预算快用完 | 「本书已花掉预算的 80%。」操作：「调高预算并继续」，打开调整对话框 |
| paused / insufficient_strawberries | 草莓不足 | 「草莓余额不足，充值后继续。」操作：「继续」 |
| paused / byok_unavailable | 自带模型不可用 | 显示后端给出的原因。操作：「去设置启用」（打开设置）、「改用平台模型」（打开调整对话框） |
| paused / decision_invalid 或 step_failed | 推演卡住了 | 「主编这一章没能给出合格的定稿（或：某一步失败），可以重试。重试会再次计费。」操作：「重试」（调用 `resume`）；显示 `last_error` 的中文摘要（如果有） |
| paused / locked_conflict | 与设定冲突 | 「档案员发现正文与锁定设定冲突，请先查看再继续。」操作：「查看」（定位到该章）、「继续」 |
| paused / daily_cap | 今日额度已用完 | 「今天的章节额度已用完，北京时间零点后可继续。」操作：「继续」 |
| paused / server_restart_failed | 恢复失败 | 「服务重启后没能自动恢复。」操作：「继续」 |
| failed | 出错了 | 显示原因，不提供操作 |

所有操作按钮在请求进行中都要显示 loading 并防止重复点击。请求出错时用 `ErrorNotice` 显示后端返回的中文原因。
