## F1【必须】工作台三栏改为按容器宽度切换（`NovelWorkbench.tsx` 等）

**现象**（实测）：
- 主页抽屉的宽度约为宿主宽度的 2/3，iframe 内又固定用三栏网格（左右两栏有 150px 和 240px 的硬下限）。
- 宿主 768×1024 时，iframe 宽 447px，文档 scrollWidth 为 462，出现横向溢出。
- 宿主 1024×768 时，正文列只剩 74px，章名每行只能排下两三个字。
- 宿主 1280×800 时，正文列只有 244px。
- 手机的三个标签页只在宿主小于 768px（`mobile:`）时才启用。

**改法**：工作台的「目录 / 正文 / 右栏」布局改用 Tailwind 4 自带的容器查询，不新增依赖。

1. 网格外层加 `@container`。
2. **容器宽度 ≥ 1040px**：三栏布局，三栏的下限大致为：
   - 目录 ≥ 180px；
   - 正文 ≥ 480px，同时保留 `max-w-[38em]` 的阅读列宽；
   - 右栏 ≥ 300px。
3. **容器宽度 < 1040px**：一律使用现在手机上的三标签页布局「目录 / 正文 / 推演·圣经·留言」。
   - 标签栏的显隐、各面板的显隐，都按容器宽度切换，不再只看 `mobile:`。
   - 页头和关卡横幅的写法不变。
4. 左右栏不能留硬下限导致溢出：栏内元素加 `min-w-0`，长文本都要能换行。

**验收**：在下面这些宿主尺寸下，都没有横向溢出（文档和任何滚动容器的 scrollWidth 都不大于 clientWidth）；正文列要么不小于 420px，要么处于标签页布局。

- 宿主 768×1024、1024×768、1280×800、1440×900、1920×1080 下，抽屉 iframe 中的工作台；
- 独立页 `/novels/{id}` 在 1024、1280、1440 宽度下。

## F2【必须】手机上向导的模型下拉框被截断，看不到价格（`NovelModelFields.tsx`）

**现象**：在 390 和 360 宽度下，原生 `<select>` 收起状态只显示「千问 3.8 Max · 每千 token 输入/输出约」，后面的价格被截掉。规格 §3 要求文字不被截断。

**改法**：
- `<option>` 的文案保持规格 §5.2 的写法不变。
- 在每个模型下拉框下方增加一行说明，显示当前所选模型的价格：
  - 平台模型显示「每千 token 输入/输出约 x/y 草莓」，用 `.readout` 显示数字，允许换行；
  - 选中 `byok:self` 时显示「我的模型（厂商·型号）· 不扣草莓」。
- 这行说明只在窄屏显示（`mobile:`）；桌面端可以不显示。

**验收**：在 360 宽度下，向导第 2 步每个已选角色的价格文字完整可见。

## F3【必须】书架、工作台请求量过大，以及授权补充两个后端字段

### 现象

1. 书架先 `GET /novels`，再逐本请求 `GET /novels/{id}`，只为拿 `max_chapters`。只要有书在运行，每 3 秒就把这一整套请求重复一遍；其中任何一本请求失败，整个书架都会变成错误态。
2. 工作台首次打开时逐章请求 `chapters/{n}`，只为拿 `edited_by_user`。一本 60 章的书，首屏要发 60 个请求。
3. 运行时工作台每 3 秒请求一次 detail、完整的 `/bible`、`/notes`，每次 load 之后还会因为 `revision+1` 再请求一次当前章。

### 授权补充两个后端字段

属于 P1 的 `backend/novel/service.py`，只增加字段，已有字段和语义一律不变：

- `summary()`（即 `GET /novels` 列表中的每一项）增加 `max_chapters`，取值为该书 `config.target.max_chapters`，整数；
- `detail()` 返回的 `chapters[]` 中每一项增加 `edited_by_user`，布尔值。

在 `backend/tests/test_novel_p2_api.py` 中补充测试：

- 两个字段都存在，且取值正确；
- 改稿以后，`edited_by_user` 变为 `true`；
- 原有字段不变。

### 前端改法

1. 书架只请求 `GET /novels`，不再逐本请求详情。
2. 工作台不再逐章补读 `edited_by_user`。
3. 运行时轮询每次只请求 detail，其他数据按需再请求：
   - `/bible`：只在 `bible_version` 变化时，或首次打开「圣经」标签时请求；
   - `/notes`：只在「留言」标签可见时、提交留言之后、或 `chapters_done` / `status` 变化时请求；
   - 当前章：只在 detail 中该章的 `status`、`words`、`flags`、`edited_by_user` 变化时，或用户切换章节时请求。

     保存改稿后只请求一次（复核 B 可优化 12）。

**验收**：

- 书架在任何情况下，每轮只发 1 个 `/novels` 请求。
- 已完结的书打开工作台，首屏不发 `chapters/{n}` 请求（当前章那一个除外）。
- 状态为 running 时，连续 3 次轮询之间，`bible_version` 不变，就不再请求 `/bible`。

## F4【必须】独立页工作台的侧栏被拉长，昼夜切换和草莓余额被推出首屏（`NovelWorkbench.tsx`）

**现象**：根容器用的是 `min-h-screen` 加整页滚动。在 1440×900 下打开独立页工作台，侧栏底部的昼夜切换和草莓余额不在首屏内（书架和向导上正常）。

**改法**：工作台改用书架和向导的同一骨架：
- 外层 `h-dvh overflow-hidden`；
- 内容区 `main overflow-y-auto`；
- 嵌入模式维持原有表现。

## F5【必须】错误显示与 404 映射（`lib/novels.ts`、工作台与子组件）

1. **同一条错误只显示一次**：`mutate` 失败时，如果错误交给子组件（SetupEditor、PlanEditor、ChapterReader、NotesPanel）在就近位置显示，页顶就不再重复显示。
2. **操作错误不能被轮询清掉**：后台轮询请求成功时，不得清除用户操作产生的错误。这类错误只在用户发起下一次操作，或手动关闭时清除。
3. **404 / 403 映射**：
   - 404 且 detail 为英文 `Not Found`（开关关闭）时，书架、向导和工作台统一显示「小说工坊尚未开放」；
   - 404 且 detail 为中文（例如「小说不存在」）时，原样显示；
   - 403 统一显示「你的账号暂未开通小说工坊」。

## F6【必须】向导与对话框的校验要和后端一致

1. **估算**：估算请求的依赖里不包含预算。修改预算不应触发 `POST /novels/estimate`，因为该接口每分钟限 20 次。
2. **调高预算并继续**（`budget_80`）：后端要求 `spent × 5 < budget × 4`。
   - 对话框里校验新预算大于 `ceil(spent × 1.25)`；
   - 不满足时就近提示「预算至少要 N 草莓才能继续」；
   - 不得出现 PATCH 成功、resume 却返回 409 的情况。
3. **立项卡**：前端字段校验要和后端的 schema 规则一致（包括人物外形不少于 20 字的计数口径，参照后端的 `compact()`），或者去掉这条前端校验，让后端判定，再把 422 映射到对应字段。不能出现「前端通过、后端 422」却不标出字段的情况。

## F7【必须】向导默认选择改为实测验证过的配置（`NovelWizard.tsx`）

**现象**：默认勾选了 5 位顾问，所有角色都用千问 3.8 Max（写手也是）。整本书估算 1.4–2.9 万草莓，与 P0/P1 实测验证过的配置不一致。

**改法**：
- 默认推演方式为 critique。
- 默认勾选三位顾问：情节架构师、人物代言人、反转设计师。
- 默认模型：

  | 角色 | 默认模型 |
  |---|---|
  | 主编 | `dashscope:qwen3.8-max` |
  | 写手 | `deepseek:deepseek-flash` |
  | 档案员 | `dashscope:qwen3.8-max` |
  | 审校（默认开启） | `dashscope:qwen3.8-max` |
  | 情节架构师 | `dashscope:qwen3.8-max` |
  | 人物代言人 | `ark:doubao-seed-2-1-pro-260915` |
  | 反转设计师 | `deepseek:deepseek-flash` |
  | 其他未勾选的顾问 | 下拉框默认为该角色可选列表中的第一项 |

- 某个默认模型不在该角色的可选列表里时，退回该角色可选列表的第一项。
- 各角色的可选列表以 `allowed_models[role]` 的顺序为准；没有限制的角色用 `catalog.models` 的顺序。

## F8【建议】章名去重显示

**现象**：模型生成的章名本身带有「第二章」，所以显示成「第 2 章 第二章 最后的底片」。目录、正文标题等处都有这个问题。

**改法**：
- 在「第 n 章」后面显示章名的地方，去掉章名开头的「第[0-9一二三四五六七八九十百零〇两]+章」以及紧随其后的空白或标点。
- 只改显示，不改存储，不改导出。

## F9【建议】小项

1. **留言时间**：留言的 `created_at`（UTC 的 `YYYY-MM-DD HH:MM:SS`）按书架 `formatDate` 的口径转成本地时间显示。
2. **伏笔章节**：伏笔账本里埋下章节为 0 的，显示「立项时」。
3. **Esc 关抽屉**：iframe 内按 Esc 关闭抽屉，仅在以下情况都不成立时生效：
   - 焦点在 input、textarea、select 或 contenteditable 中；
   - 正处于输入法组字状态（`isComposing`）；
   - 有打开的 dialog。
4. **抽屉外壳**：书斋抽屉的关闭按钮与「设置」抽屉完全一致（桌面端 `w-6 h-6`，手机端 `max-md:h-10` 等，照抄 class）。面板加 `outline-none`，避免程序聚焦时出现焦点框。
5. **嵌入模式底部留白**：嵌入模式下工作台不加底部的 tabbar 留白（抽屉本身已经停在底栏上方）。
6. **无障碍**：
   - 标签页的 `aria-controls` 必须指向实际存在的元素；
   - 手机和窄容器的三个栏目加 `role="tabpanel"`；
   - 当前章用 `aria-current="true"`。
7. **目录标记**：目录标记里的 Unicode 符号（⚑、◷ 等）改用 lucide-react 的图标（已是依赖）。保留文字说明和 title。
