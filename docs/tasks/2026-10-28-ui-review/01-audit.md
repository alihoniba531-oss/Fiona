# 前端 UI 全面复核（2026-10-28）

## 范围与方法

- 代码基线：main `58be576`（含 10-27 的 UI 打磨与依赖升级）。
- 环境：隔离实例。后端 8097 用一个全新的空库，前端 3097 是 dev 服务器，不碰用户的 3000 / 8010。空库里灌了样例数据，专门覆盖界面要承载的几种内容：
  - 一条带 Markdown 的分身回复（二级标题、有序列表、无序列表、引用、行内代码、强调）；
  - 一张生成图、一张用户上传的照片；
  - 跨两天的消息（看日期分隔）；

- 路径：主页，六个抽屉按真实点击打开（分身、广场、世界、设置、书斋、工作室），手机底栏四个抽屉，手机对话目录弹层，输入区图片菜单与输入态；独立路由 /login、/history、/match、/profile、/community、/agents、/novels/new、/studio/kb、/settings。

- 对照物：`docs/tasks/2026-10-06-song-liquid-glass-ui/design/shots/` 里的定稿画板（Chat、ChatMobile、Agent、World、Settings、Main）。
- 截图只留在会话临时目录，不进仓库。

## 总体判断

- 方向已经成立。登录页、对话页、分身页、广场、设置页和画板逐一对照，结构、材质、字号层次基本一致；昼夜切换无闪烁；抽屉的 `inert` / `aria-hidden` / Esc 契约都在；Markdown 安全子集渲染（10-27 新做）在桌面和手机上都排得干净，悬挂缩进、引用竖线、无粗体，比画板里的纯文本更耐看。这些不用动。
- 差距集中在三处，不是「像不像设计稿」的问题：
  1. 手机端还有几处看得见的 bug（点输入框页头被顶掉、「回到最新」压正文、对话目录弹层露缝）。
  2. 后长出来的模块（书斋、工作室、本机监控、聊天模型）各自为政：标题重复、双 CTA、原生弹窗、说明文字一整屏。
  3. 系统层的债：旧 shadcn 令牌和新令牌双轨、30 种字号、`--ink3` 对比度不够、焦点样式只盖住 `.btn/.chip`。
- 10-26 清单回访：第 1–10 条已修并在本次实测中确认；第 11 条（独立 /studio 侧栏偏低）本次未复测；第 12 条星图被列表盖住仍在；第 13 条匹配页空态仍在。第 7 条「手机抽屉露缝」六个抽屉已修好，但对话目录弹层漏掉了（见下 P1-4）。

## 问题清单

### P1：看得见的错误或明显妨碍使用

1. **手机点输入框后，整个对话外壳被顶上去 40px，页头被裁掉。**
   - 现象：390×844 下点「说点什么…」或打开图片菜单，页头（朱印、名字、朗读 / 免提）上移，只剩下半截；页面本身没有滚动（`document.scrollingElement.scrollTop` 为 0）。
   - 根因：`app/page.tsx:2387` 的 `.chat-shell … overflow-hidden`。浏览器把焦点元素滚进可视区时，滚动了这个 `overflow:hidden` 的容器，实测 `chat-shell.scrollTop = 40`。真机弹出软键盘只会更明显。
   - 改法：`.chat-shell` 改用 `overflow-clip`（不可被程序滚动），或在聚焦后把它的 `scrollTop` 归零。
   - 验收：手机聚焦输入框后，`.chat-header` 的 `getBoundingClientRect().top` 仍为 0；桌面不变。

2. **「回到最新」浮标压在正文中间。**
   - 现象：手机上它浮在屏幕中部，盖住「按你说的分三天…」一行和生成图；桌面上也离输入釉片很远。
   - 根因：`components/ChatScrollArea.tsx:139` 用 `bottom: calc(var(--chat-content-bottom) + 96px)`，而 `--chat-content-bottom` 本身已含输入区高度 + 底栏 + 50px 余量，再加 96px 就到了屏幕中间（手机约 357px）。
   - 改法：贴着输入釉片上沿定位：桌面 `bottom: calc(var(--composer-height) + 24px)`，手机再加 `var(--tabbar-h) + env(safe-area-inset-bottom)`；样式改用 `.chip`，去掉 `bg-background/95 shadow-sm` 这组旧写法。
   - 验收：浮标下沿与输入釉片上沿的距离 ≤ 24px；不与任何消息重叠（截图比对）。

3. **每条分身消息下面的小喇叭是个死按钮。**
   - `components/ChatBubble.tsx:290` 与 `:400–408`：点击只在 `Volume2` / `VolumeX` 之间换图标，`muted` 没有接任何朗读逻辑。用户会以为能单条朗读或静音。
   - 改法（见「待拍板」第 1 条）：按画板，这一行是「朗读 复制」两个 12px 文字按钮。建议改成 时间 / 朗读 / 复制 / 删除 四项文字按钮，删除不再只靠 hover 出现（hover 在触屏上不可靠）。「朗读」接单条 TTS，正在读时文字变「停止」。

4. **手机对话目录弹层露缝，透镜把底下的字折成乱码。**
   - 现象：打开「对话列表」后，右侧露出输入釉片「发送」按钮的一角；左下角「每条消息消耗 10 颗草莓」被透镜折成不可读的字形。
   - 根因：10-26 第 7 条只处理了 `.drawer-panel`（六个抽屉），`app/page.tsx:2476` 的 `.chat-conversation-modal` 没有同样处理，边缘遮罩与透镜还在。
   - 改法：手机上对 `.chat-conversation-modal > .glaze` 同样去掉边缘遮罩、关掉透镜；弹层外加 `--scrim` 遮罩盖住底下的页面。
   - 验收：390×844 打开目录后，视口右缘 0–390px 内不出现输入釉片的任何像素；底下文字不可见。

5. **对比度：淡墨三号 `--ink3` 昼主题只有 2.79:1。**
   - 按令牌值算：昼 `--ink` 12.7、`--ink2` 5.3、`--ink3` 2.8、`--seal` 5.7；夜 `--ink` 14.4、`--ink2` 7.2、`--ink3` 3.9、`--seal` 3.6。
   - `--ink3` 用在 Markdown 列表圆点、三级标题、辅助说明；夜主题的朱字（`--seal`）用在「永久删除账号」「清空记忆」等 13–15px 文字上，不到 4.5。
   - 改法：昼 `--ink3` 加深到约 `#6F7C76`（≈3.6，只许用于装饰与 ≥18px 的字），文字一律改 `--ink2`；夜主题朱字另加一枚文字用 `--seal-ink`（约 `#D4604F`，≈5:1），`--seal` 继续用于印章与边线。
   - 验收：全站正文 ≥ 4.5:1、辅助文字 ≥ 3:1，用脚本对令牌对算一遍。

### P2：一致性与信息密度

6. **旧令牌与新令牌双轨。** `text-muted-foreground` 145 处、`text-foreground` 28、`bg-secondary` 19、`bg-muted` 8、`text-destructive` 8，与 `text-[var(--ink2)]` 34 处并存，另有 36 处行内 `style` 写颜色。功能上靠 `globals.css:281–297` 的别名落到同一个色，但同一灰度有三种写法，改色时必漏。改法：一次机械替换成新令牌（`--ink`、`--ink2`、`--slip`、`--seal`），别名只留给 `components/ui/*`；`.typing-cursor` 用的 `--amber-ink`、`--rec`、`--dim` 这些旧名一并清掉。

7. **字号 30 种。** arbitrary 字号 28 档（9、10、10.5、11、11.5、12、13、13.5、14、14.5、15、16、16.5、17、17.5、18、18.5、20、22、23、26、28、30、32、46、64、76 与 0.8rem），加 `text-xs/sm/base/lg/xl`。单独一个对话页上实测就出现 11 / 12 / 13 / 14 / 15 / 15.18 / 16 / 16.5 / 18 / 18.5 / 30 十一种。改法：定一张 8 档字阶写进 `globals.css`——11 / 12 / 13 / 15 / 16.5 / 18 / 22 / 30，展示字 46 / 76 另列——以 `--fs-*` 令牌替换，之后用 grep 门禁禁止新的 `text-[Npx]`。

8. **工作室抽屉仍带自己的大标题，书斋抽屉双 CTA。** 嵌入时「工作室」页眉下还有 30px 的「短片工作室」和「+ 新建项目」，与分身 / 设置 / 世界已改的做法（10-26 第 6 条）不一致。书斋空态同时有右上角「+ 新建一本」和空态卡里的「新建一本」。改法：`components/studio/StudioShelf.tsx` 在 `embedded` 时隐藏 h1；`components/novel/NovelShelf.tsx` 空态只留卡内一个按钮，右上角按钮有书之后再出现。

9. **原生 `confirm()` / `alert()` 共 16 处。** 设置页清空与删号、删对话（`app/page.tsx:1609`、`:1775`）、上传校验（`:2215`、`:2219`）、删规则、清记忆、删 Key、删书。浏览器默认弹窗和影青釉完全脱节，桌面壳里也不可定制。改法：一个共用的 `<dialog>` 确认组件，样式复用 `.image-preview-dialog` 与工作室 `QuoteDialog`；文案沿用现有，危险操作主按钮用朱字。

10. **空态太轻。**
    - 新对话：只有一行 12px「和 Chloe 开始新的交流。」贴在顶部，下面整屏空白。
    - 匹配页：右侧整片空白，左栏一行 11px「接受匹配后会出现在这里」（10-26 第 13 条仍开着）。
    - 画像页标题「旧社交画像」是系统叫法，用户不知道「旧」是相对什么。
    - 改法：空态要给动作。新对话给 2–3 个可点的开场（例如「聊聊今天」「帮我画一张…」「看看我拍的这张图」）；匹配页说明匹配是什么，并给「去开公开名片」的入口；画像页改名「社交画像（旧版）」或并入分身页的私有记忆。

11. **设置页信息密度。** 「聊天模型」一节的隐私说明是 7 段 13px 连排，1440×900 下占满一整屏，找「保存」要翻过去。改法：收成「隐私说明」折叠（`<details>`）或只留三句 + 「查看完整说明」；这一节本身也可拆成「用谁回复 / Key / 高级」三块。

12. **手机输入区空闲高度 151px**（10-26 的目标 ≤ 140），其中「每条消息消耗 10 颗草莓」单独占一行。改法：费用提示合进工具行发送键左侧的小字，或只在首次与余额低于 30 时显示（见「待拍板」第 4 条）。

13. **粗体残留 3 处。** `app/page.tsx:217`「神秘好友」、`:2420`「当前对话记录」、`:2440` 日期标签用了 `font-semibold`，违反「界面文字不加粗」。改成常规字重，层次靠字号与灰度。

14. **中点分隔 58 处，新写的文案仍在用「·」。** 输入区模型标签「… · 不扣草莓」、提醒 chip「有新的本机提醒 · …」、写歌卡「第 N 稿 · 状态」、设置「Chloe AI 助理 · 内测版」、工作室价格「… · 1.2 秒」。10-06 规格 §8 明确不许。改法：改用细竖线（页头「AI 分身｜仅你可见」已是这种做法）、换行或括号；保留规格列明的既有必须原样文案。

15. **焦点样式只盖住 `.btn` / `.chip`。** `outline-none` 40 处里 10 处没有任何 `focus-visible` 替代（输入框、文本域、抽屉容器）；书签导航、对话列表项、消息行小按钮、主题圆钮用的是浏览器默认蓝色轮廓，与墨线不符。改法：`globals.css` 加一条全局 `:focus-visible { outline: 1px solid var(--ink); outline-offset: 3px }`，输入框用 `focus:border-[var(--ink)]`。

### P3：次要

16. 手机抽屉底边与底栏之间有一道釉口阴影，像没盖严。抽屉下沿与底栏上沿都在 784px，缝不是空隙，而是 `.glaze-finish` 的积釉渐变和 `lipdk` 线在边到边的抽屉上成了一道横线。手机 `.drawer-panel > .glaze-finish` 去掉底部内阴影即可。
17. 消息入场动画 `msg-in-left/right`（0.2s 滑入）每条都有，切换对话时整列一起滑，是「每张卡都动」的套路；只给新到的那条动。
18. 世界抽屉桌面 1440 宽时星图被两侧列表盖掉大半（10-26 第 12 条仍开着）。要么列表釉片提高透明度让星图透出来，要么把星图缩到中间 520px。
19. 历史页日期筛选是原生 `<input type="date">`，显示「日/月/年」占位，和整页宋体不搭。可改成两枚 chip 弹日历，或保留但套 `.readout` 样式并用中文占位。
20. `/novels/new` 在已登录状态下等了 3 秒仍显示「请登录后新建小说。」（需核实：是身份加载前的文案被当成终态，还是向导读身份的来源和书架不同）。身份未定时应显示「正在加载…」。
21. 「语音」按钮轻点转文字 / 按住说话的双功能没有任何可见提示，`title` 只有桌面 hover 能看到。首次使用给一次性气泡说明，或在按住时显示「松开发送」。
22. 匹配页独立打开时没有侧栏（其他独立页都有），只有「最近聊天」一栏贴在左上。平时它在抽屉里，影响小。
