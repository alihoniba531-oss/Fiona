# 04 第 2 轮返修单（r2）

第 2 轮复核：R1-1 至 R1-25 中 22 条确认修好；下列 3 条经对抗式复核仍成立，另加 2 条小的回归。只修这些，不要改动其他已通过的部分；不要回滚，不要提交 commit；文档白名单仍为 README.md 与 docs/DEPLOYMENT.md。改完重跑规格 §10 第 1–7 条。

**R2-1 iframe 抽屉头部透底（R1-14 引入）**：世界、设置两个 iframe 抽屉外壳按 R1-14 去掉了 lens 与 blur 后，抽屉头部行（标题、标签、关闭按钮所在的那一条，位于父文档、不在 iframe 内）背景完全透明，底下主页面页头的文字透上来与抽屉自身文字重叠（桌面、手机，昼夜都有）。修法：头部那一条要有可读的底——给头部行加不透明的 `var(--hi)` 底（素瓷下同样成立），或只为头部那一条保留 blur 层；iframe 区域照旧不做 backdrop。验收：打开两个抽屉，头部文字下面看不到主页面的任何文字。

**R2-2 globals.css 分层整理带来外观回归（R1-24 未完成）**：`@layer components` 的闭合括号原在 `.bubble-ai` 之后，被挪到了文件末尾附近，导致原本无层的全局规则（主题类、ink-landscape、手机 40px 触控、消息入场动画、滚动条、手机输入框字号等）全部进了层内，优先级改变。已发现的外观变化：手机 /agents/me 与分身抽屉里「头像符号」输入框字号从 32px 降到 16px（手机输入框字号规则被包进层并加了 `!important`）；`.image-model-segments .chip` 的 min-width 规则同理受影响。修法：恢复 `@layer components` 在 `.bubble-ai` 之后闭合，把这批全局规则放回层外原位置，去掉为补救而加的 `!important`；Glaze 与对话页规则仍按 R1-24 合并在层内。验收：手机头像符号输入框字号恢复 32px（并仍 ≥16px 的不变量）；对照第 1 轮截图外观无其他变化。

**R2-3 贴底时最新消息的元信息行被底部渐隐压淡（R1-4 与 R1-3 叠加）**：内容底部留白（`--chat-content-bottom`：桌面 composer+36px，手机 composer+tabbar+安全区+20px）小于底部渐隐带的上界（桌面 composer+18+48，手机 composer+tabbar+安全区+48），贴底静止时最后一条回复的时间与朗读按钮落在渐隐带里，只剩约 50%（桌面）/ 70%（手机）不透明度。修法：把 `--chat-content-bottom` 加大到不小于渐隐带上界（桌面约 composer+66px，手机约 composer+tabbar+安全区+50px），`scroll-padding-bottom` 共用同一变量随之变化；「回到最新」按钮相应上移，不要压住最后一行正文。验收：贴底静止时最后一条消息（正文、时间、朗读按钮）不透明度为 1；用 Tab 移到渐隐带附近的按钮时焦点不落在半透明区；R1-4 的条纹判据仍成立。

**R2-4 生图模式下模型选择组的顺序变了（R1-19 引入）**：桌面生图模式下，模型选择组现在排在「返回聊天 / 全部取消」之后，以前在它们之前，视觉顺序与键盘顺序都变了。修法：恢复改造前的先后顺序（模型选择组在前），手机端仍按 R1-19 用 grid-area 放到文本框上方。

**R2-5 首帧脚本 read() 在键不存在时不回落默认值**：`localStorage.getItem` 返回 null 时应返回传入的 fallback（仅在抛错时才回落 dataset 的逻辑保持），避免在「setItem 抛错、getItem 正常」的环境里切换主题失效。
