# 修改意见卡 · 派单方验收脚本与结果

这些脚本由派单方在实施方沙箱外运行，用来独立核验实施结果。它们不是产品代码，也不进 CI。路径一律通过环境变量或命令行参数传入。

## 脚本

- `gate.sh`：规格 §5 的确定性门禁，依次跑：
  - 三个新测试文件；
  - 25 个既有测试文件；
  - 后端全量；
  - `tsc`、`lint`、`build`；
  - 无 `node_modules` 副本。

  用法：`WT=<工作树根> NONODE_DIR=<仓库外临时目录> gate.sh <输出目录>`。
- `mut_feedback.py`：变异测试，共 93 项，三类：
  - R0 原有 61 项；
  - R1 新增 23 项，含复核方记录的存活变异，以及「点重新定稿先重读」与章号核对；
  - R2 新增 9 项。

  每项在写时复制克隆里把实现改坏一处，跑对应的新测试文件（排除 `test_bad_` / `self_check` 自检），必须变红。用法见文件头。
- `seed_feedback.py`：走查造数，内容全部虚构：四本书、七张卡。
- `walk_feedback.py`：Playwright 真实界面走查，三种宽度 1440 / 1280 / 390。其中「R1」一段直接改临时库，模拟作者在书斋里改了主编模型或确认方式，然后不刷新卡片直接点「带着这些要求重新定稿」。
- `walk-env.sh`、`walk-backend.sh`、`walk-web.sh`：隔离走查环境，8063 后端 + 3063 前端 + 临时库，需先设置 `WTC`、`D`。

## 结果（`results/`）

- `gate-r2-summary.txt`：R2 门禁摘要，另含 HEAD `7a17f64` 对照与走查摘要。
  - 后端全量 8264 passed，0 skipped。
  - 在 `7a17f64` 上跑新测试，失败全是 `AssertionError`。
- `mutations-r2.txt` / `mutations-r2.json`：93 项变异全部被杀。
- `mutations-r2ctl-on-r1.txt`：正控。§4.7 新加的 9 个变异在 R1 版测试上全部存活，证明这些测试缺口确实存在。
- `walk-r1.txt`：走查 49/49 通过。R2、R3 没有改产品代码。
  - 同一套 R1 检查在 R1 之前的代码上做过正控：6 项变红，其余 19 项通过。
