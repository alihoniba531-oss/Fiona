## 一、场景类型清单（19 类）

用法：划场之后，导演模型给每场打 **1 个主类型**，必要时再加 **1 个次类型**（见文末裁决点 1）。「开场钩子」和「结尾悬念」按位置判定，可以和内容类型叠加。

| # | id | 名称 | 一句定义 | 识别信号（剧本里出现什么就算） | 易混与改判 |
|---|---|---|---|---|---|
| 1 | `scene.establishing` | 环境建立 | 交代新地点、时间、天气或世界规则，没有主要剧情动作，人物可有可无 | 某个地点第一次出现；出现「清晨 / 深夜 / 远处 / 城门外」这类时空描写；时间跳跃后的第一段；只有环境描写、没有台词 | 空镜里有悬念物（门缝、血迹）→ 揭示或蓄势；集首第一场先看是否算开场钩子 |
| 2 | `scene.opening_hook` | 开场钩子 | 集首 3–10 秒内用反常画面、冲突或断言抓住观众，不负责交代前情 | 本集第 1 场的开头；剧本标「冷开场 / 倒叙 / 钩子」；一句反常识断言（如 P02「螺丝松不是因为振动」）；直接从危机中段切入 | 按位置判定，常叠加揭示、打斗作次类型 |
| 3 | `scene.dialogue` | 对话 | 两到三名角色以交换信息、推进关系为主的文戏，冲突还没升级成对抗 | 两到三名角色的台词交替至少两轮；以询问、告知、商量为主；动作少（坐、站、端茶、递物、边走边说） | 出现质问、威胁、拍桌、逼近 → 争执对峙；只一人说 → 独白；三人以上都有反应戏 → 群戏 |
| 4 | `scene.confrontation` | 争执对峙 | 立场对立的双方用语言、姿态或距离施压，还没动手或即将动手 | 质问、威胁、冷笑、怒视、拍桌、步步逼近、长时间对视沉默；一坐一站这类高度差或权力差 | 一旦有肢体攻防 → 打斗；意见不同但语气平和 → 对话 |
| 5 | `scene.fight` | 打斗 | 有肢体或兵器接触的对抗，按回合推进到胜负、中断或僵持 | 连续出现劈、砍、刺、格挡、闪避、出拳、踢、摔、过招；明确写到击中、相撞、兵器脱手、倒地 | 只有逼近、没有攻防 → 争执对峙；一逃一追、接触偶发 → 追逐；法术远距离对轰 → 奇观 |
| 6 | `scene.chase` | 追逐 | 一方逃、一方追，持续的空间移动和距离变化是张力核心 | 跑、追、逃、甩开、拐进、翻墙、撞翻摊子；出现「身后 / 追兵 / 车灯逼近」；有时间或距离压力 | 追上后交手 → 转打斗；只有一人奔跑、没有追兵 → 蒙太奇或蓄势 |
| 7 | `scene.action_insert` | 动作特写 | 以一个关键物理动作或道具、机构操作为信息核心，靠放大细节讲清「发生了什么」 | 手部或道具动作是信息核心（开锁、递信、扣扳机、拧紧螺丝）；「缓缓 / 轻轻 / 拧 / 按 / 抽出」；机构原理演示（P01 丝杠、P02 螺丝） | 以旁白讲解为主、画面只是证据 → 旁白讲解；打斗里的一招 → 属于打斗的插入镜 |
| 8 | `scene.reveal` | 悬疑揭示 | 先遮住、后揭开关键信息（身份、物件、真相），由镜头控制观众何时得知 | 「原来 / 竟然 / 赫然 / 定睛一看」；门后、帘后、镜中、转身露脸；发现尸体、线索、伤口；掀开盖布 | 揭开的东西推翻了前文的理解 → 反转；只蓄势、还没揭开 → 紧张蓄势 |
| 9 | `scene.tension` | 紧张蓄势 | 危险逼近但还没发生：躲藏、潜行、等待、倒计时，靠拖延和声音制造压力 | 屏住呼吸、躲进柜子、脚步声逼近、门把转动、倒计时、「不敢出声」 | 本集结尾停在揭开前一刻 → 结尾悬念；揭开那一下 → 揭示 |
| 10 | `scene.monologue` | 情感独白 | 单人承载情绪：内心独白、倾诉、哭诉、自语，表演和留白是主体 | 单人长台词或内心 OS；「独自 / 默默 / 想起 / 喃喃」；情绪词密集、动作少 | 另一人有回应 → 对话；画面转入过去 → 回忆闪回 |
| 11 | `scene.flashback` | 回忆闪回 | 跳回过去的段落（整场或插入式），必须有清楚的进出标记 | 「那年 / 多年前 / 想起 / 记得」；时态变化；剧本标「回忆」；同一人物年龄、服装、伤痕不同 | 想象、梦境也归本类，标注「非真实时空」 |
| 12 | `scene.ensemble` | 群戏 | 三人以上同场且多人有戏（会议、宴会、审讯、团队行动），核心是调度观众注意力 | 三名以上有名有姓的角色同场发言或有反应；「众人 / 全场 / 满座」；宴会厅、朝堂、会议室 | 背景群众不说话、只有两人有戏 → 对话；多人混战 → 打斗 |
| 13 | `scene.montage` | 过场蒙太奇 | 用一串短镜压缩时间或并列同类信息（训练、旅途、筹备、时间流逝） | 「几天后 / 日复一日 / 一路上 / 从此」；列举式动作；没有台词，只有旁白或配乐 | 镜与镜之间有因果、动作要连续 → 按内容类型拆 |
| 14 | `scene.twist` | 反转 | 先让观众相信一种理解，再用一个信息推翻（身份、立场、局势逆转），需要前后对照 | 「其实 / 没想到 / 原来他才是」；前文铺垫被推翻；情绪急转（冷→暖、胜→败） | 只是新信息、并不推翻前文 → 揭示 |
| 15 | `scene.cliffhanger` | 结尾悬念 | 集尾 5–15 秒留下未解问题或迫近的危机，停在答案之前 | 本集最后一场；分集方案「终点 / 钩子」一列；「就在这时 / 门开了 / 电话响了」；突然出现的人、物、消息 | 按位置判定，常叠加揭示、蓄势作次类型 |
| 16 | `scene.explainer` | 旁白讲解 | 旁白或口播主导，画面是插图式证据，常见于科普和产品讲解（Preloq 这类） | 旁白占满时长、角色不开口；术语、数据、「为什么 / 原因是」；需要角标、图表等精确文字（走 post_only） | 画面里有角色对话 → 对话；只拍一个机构动作 → 动作特写 |
| 17 | `scene.spectacle` | 奇观异象 | 以超自然或大尺度视觉事件为主体（法术、变身、巨物降临、天象异变），人物只是尺度参照 | 法术、变身、显圣、巨兽、天裂；「光芒 / 化作 / 降临」；仙侠玄幻的高潮段 | 有近身攻防 → 打斗；只为交代世界观的远景 → 环境建立 |
| 18 | `scene.intimate` | 温情亲密 | 以身体接触或近距离传递情感：拥抱、牵手、依偎、告别、和解 | 拥抱、搀扶、擦泪、抚摸头发、额头相抵、挥手告别；台词少、动作慢 | 主要靠说话推进 → 对话（慢档）；只有一人 → 独白 |
| 19 | `scene.comedy` | 喜剧包袱 | 按「铺垫 → 停顿 → 抖包袱 → 反应」的节奏制造笑点 | 误会、出糗、反差、吐槽、夸张反应；剧本标「笑点」；一句话后全场愣住 | 轻松对话但没有明确包袱 → 对话（快档） |

和任务单列举的 14 类相比，新增 5 类：
- **紧张蓄势**：从「悬疑揭示」里拆出来。揭开前的拖延和揭开那一下，拍法相反。
- **旁白讲解**：Preloq 这类科普片和端到端验收要用。
- **奇观异象**：仙侠、神话题材的高潮段。版权和特效风险集中在这一类。
- **温情亲密**：拥抱、搀扶这类肢体接触是 AI 穿模的高发区，需要单独的降级方案。
- **喜剧包袱**：节奏规则（包袱前停顿）和对话不同。

## 二、样卡怎么读

两张样卡用的是同一套字段，正式的 `SCHEMA.md` 会按样卡定稿。

| 字段 | 内容 | 机器怎么用 |
|---|---|---|
| `id` / `title` / `version` / `status` | 卡片身份；`status` 取 `draft → reviewed → approved` | id 必须与文件路径一致 |
| `definition` / `summary` | 一句定义；给导演模型看的要点 | 原样注入提示词 |
| `tags` | 适用的节奏、情绪、人物数、画风、室内外（受控词表） | 按标签过滤取卡 |
| `signals` | 强信号、弱信号、改判信号（`route_to_ref`） | 导演模型打标签时参照 |
| `directing` | 导演要点 | 注入 |
| `beats` | 节拍，含时长占比区间 | 校验：下限之和 ≤ 1 ≤ 上限之和 |
| `coverage` | 推荐镜头顺序（C1、C2……），景别、角度、运镜全部引用语法卡 id | 每镜的「依据」可以填 `scene.dialogue#C2` 这类锚点 |
| `pacing.tiers` | 快 / 中 / 慢三档：成片镜长、每分钟镜头数、生成放大系数 `gen_ratio` | 校验：每分钟镜头数 = 60 ÷ 镜长；`gen_ratio` 供报价估算 |
| `generation` | 生成与裁切策略（最少 4 秒） | 注入 |
| `camera` | 默认运镜 / 可用 / 仅非敏感镜头可用 / 避免，全部引用语法卡与反例卡 | 知识库检查：敏感镜头出现运镜即报 warning |
| `sound` | 声音要点 | 注入 |
| `ai_risks` | 风险条目：适用通道与画风、症状、对策、降级、等级（P0/P1/P2） | 按所选模型和画风过滤后注入 |
| `example` | 一场完整示例：机位长条 → 裁成哪些镜 → 台词落在哪 | 注入，案例库建起来以后可以换成真实案例 |
| `sources` | 来源 id，登记在 `SOURCES.md` | 校验：来源都已登记 |

引用规则（拟定）：以 `_ref` / `_refs` 结尾的字段一律填卡片 id；卡内条目用 `卡片id#条目id` 定位，例如 `scene.fight#R1`。卡内条目 id 的前缀固定：节拍 `B`、镜头顺序 `C`、风险 `R`、示例里的生成条 `G`、示例里的成片镜头 `E`。

## 四、要你拍板的点（回复编号即可，比如「1 同意，2 选 B」）

1. **一场打几个类型标签**。我的建议：主类型 1 个，次类型最多 1 个。取材料时取主类型模板全文，次类型只取它的 `ai_risks` 和 `camera.avoid`，这样注入量可控。
2. **打斗快切的默认做法**。
   - **A（建议默认）**：单机位连续动作长条，每条 5–6 秒，裁成 2–3 镜，与其他机位交叉。依据是侠客行实测：30 秒 9 剪，均值 3.3 秒。
   - **B（可选，需先跑探针）**：万相官方短剧做法，一条 10–15 秒里写 6–8 个时间戳分镜，每段 1.4–2.3 秒。缺点是首帧只锁第一个分镜，之后的分镜身份容易漂移。
3. **「每镜最多 2–3 个动作」在打斗里怎么数**。我的建议：一串同类连续交击（「连续对砍数刀」）算 1 个动作单元，只有单独细写的记忆点动作（锁刃 → 弹开、错身一刀）各算 1 个。不这么数的话，侠客行 8 条全部超标，知识库检查也会一直报。
4. **对话口型的默认档**。我的建议：默认 `avoid`，说话人不露可读嘴形（过肩背面、侧后、远景、遮挡），情绪交给听者反应。真口型 `sync` 一律算 P0，单独报价、先跑探针。原因：本机 MCP 的万相和 Seedance 都不支持参考音频输入，原生口型用的是模型自己的声音，和定档声线对不上。
5. **节奏数值和第三方 Skill 冲突**。ai-visual-director 的快切是 0.5–1.5 秒/镜，我不采用：它低于 4 秒最少生成，也不符合一集约 60 镜的口径。本库快档下限取万相官方的 1.4 秒，而且只能通过「一条生成、裁成多镜」实现。
6. **写实对话的默认通道是万相**。Seedance 写实正脸过不了肖像闸，所以 Seedance 只接动漫画风（蓝海囚笼 v2 实测露脸可过），或者背影、逆光剪影镜头；3D 画风还没实测。万相打斗也还没实测过，写实打斗如果走万相，先跑一条 5 秒探针。
