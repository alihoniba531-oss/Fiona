### 我在真实浏览器里验证过的一种做法（H 与 J 一起解决）

我用临时内联样式在返修 1 的页面上试过下面的做法，三种布局都成立。你可以照做，也可以用别的办法；以第三节的数值为准。

返修 1 的结构（群聊标签，从外到内）：

```
div.relative.flex.h-dvh.overflow-hidden                 外壳
  main.min-h-0.flex-1.overflow-y-auto                   页面滚动的盒子（手机上带 mobile:pb）
    div.@container.flex.h-full.min-h-0.flex-col.py-5    内容容器            ← 写死 h-full
      div.flex.h-full.min-h-0.flex-col                  房间根节点          ← h-full
        div.mt-4.flex.min-h-0.flex-1.flex-col           标签条以下的区域
          …（中间还有四层 flex min-h-0 flex-1 flex-col）
            div.min-h-0.flex-1.overflow-y-auto          消息区（真正滚动的盒子）
```

做法：

1. `main` 改成纵向的 flex 容器（仍然 `overflow-y-auto`）。
2. 从内容容器起，到「被限高的那个盒子」之前的每一层：去掉 `h-full`，改成「可以被拉高、不能被压矮、基准是内容高度」，也就是 `flex: 1 0 auto`。
3. 「被限高的那个盒子」用 `flex: 1 1 0px`（基准必须是 0px，见下面的坑）加一个最小高度，自己 `overflow-y-auto` 或把高度交给里面的滚动盒子：
   - 窄布局的群聊标签：这个盒子是消息区，最小高度 120px。
   - 宽布局：这个盒子是两栏的那个 grid，最小高度 320px；grid 里面沿用返修 1 的写法（`grid-rows-[auto_minmax(0,1fr)]`，两栏各自内部滚动）。
4. 其余页面（列表、新建、加载中、出错、无权限、找不到，以及窄布局的方案、成果、来源标签）只需要第 1、2 步：内容多高，容器就多高，下内边距自然在内容之后。

一个坑：Tailwind 的 `flex-1` 是 `flex: 1 1 0%`。父级高度不确定时，百分比基准会被当成「内容高度」，消息区就按它的全部内容（几万像素）计入，页面会被撑得极长。被限高的盒子的基准要写成 0px（例如 `basis-0`，或 `flex-[1_1_0px]`），不能是 `0%`。

内联样式实验的结果（「等你决定」的群）：

| 布局与视口 | 页面是否滚动 | 被限高的盒子 | 滚到底后的底部留白 |
|---|---|---|---|
| 抽屉群聊 1280×900 | 不滚动 | 消息区 356px（与返修 1 相同） | 20px |
| 抽屉群聊 1280×620 | 可滚 44px | 消息区 120px | 20px |
| 抽屉群聊 1280×440 | 可滚 224px | 消息区 120px | 20px |
| 宽布局 1920×1000 | 不滚动 | 两栏 787px（与返修 1 相同） | 20px |
| 宽布局 1920×520 | 可滚 13px | 两栏 320px（其中消息区 132px） | 20px |
| 手机宽度列表页 390×780 | 可滚 | 无 | 最后一张卡片在导航栏之上 20px |
